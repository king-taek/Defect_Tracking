# DONE · Fluent 재설계 대조표

`PLAN-FINAL.md` 의 단계 0a~9 를 구현한 결과를 화면별로 대조한다. **못 지킨 것은 숨기지 않고
그대로 적는다.** 판정은 세 가지다.

- **일치**: 명세대로 구현했고 라이트·다크 렌더로 눈으로 확인했다.
- **이탈**: 명세와 다르게 만들었다. 이유를 적었고 되돌릴 수 있다.
- **미구현**: 하지 않았다. 이유와 재개 조건을 적었다.

Q1(qfluentwidgets GPLv3, 비상업 한정)은 2026-08-23 사업 주체의 **진행** 결정으로 기록했다
(`PLAN-FINAL.md` §5). 되돌릴 지점은 커밋 `3e98452`(의존성 고정) 하나다.

## 3. 성능 실측

offscreen, 병렬 부하가 있는 환경에서 측정했다. 목표는 `PLAN-FINAL.md` §검증.

| 규모 | 지도 모드 | 래스터 rebuild | paint (선택 없음) | paint (선택 250칸) | 영역 합산 |
|---|---|---|---|---|---|
| 42 die | detail 45px | 해당 없음 | med 0.85 ms | med 0.85 ms | < 0.01 ms |
| 1,024 die | plain 12px | 해당 없음 | med 4.66 / p95 5.79 ms | med 6.15 / p95 8.60 ms | < 0.01 ms |
| 4,096 die | raster 6.2px | avg 3.42 / max 3.93 ms | med 0.13 / p95 0.23 ms | med 1.69 ms | < 0.01 ms |
| 16,384 die | raster 3.1px | avg 12.4 / max 15.0 ms | med 0.14 ms | med 1.53 ms | < 0.01 ms |

목표 대비: rebuild < 100 ms → **3.4 ms**, paint < 16 ms → **0.13 ms**(4,096 die).
1,024 die 벡터 경로가 최악이라 같은 색 칸을 묶어 `drawRects` 한 번으로 보내도록 고쳤다
(med 13.9 → 4.66 ms). 선택 칸이 256개를 넘으면 링을 낱개로 그리지 않고 경계 사각 하나로
묶는다(3,000칸에서 10 → 1.8 ms). `set_data` 전체는 4,096 die · 24,972 defect 에서 약 180 ms
인데 대부분 `cluster_records` 이고 누적합 재구성만은 1.8 ms 다.

| 그 밖 | 수치 | 조건 |
|---|---|---|
| 폴더 목록 `_go_to` (UI 스레드) | 17 ms | 하위 300개. 현재 폴더 아래를 다시 읽지 않음(테스트로 고정) |
| 판독대 12칸 | 칸 높이 224 px 유지 | 1464x940 창, 4열 x 3행, 세로 스크롤 발생 |

실행으로 같은 범위를 덮는다.

## 6. 남은 것

- µm 스케일바 2곳(판독대 기준 칸 · 뷰어 무대). 픽셀↔µm 실비율 근거가 생기면 구현한다.
- 설정의 경로 직접 입력. 되살릴지 사용자 판단이 필요하다.
- Excel Q4 의 교차 그룹 블록(기준 없음 모드)은 후속 범위로 남겼다.
- 한 프로세스 전체 실행이 멈추는 문제(위 §5).
- `theme.py` 의 레거시 `STYLESHEET` 와 `build_bridge_qss`. 아직 옛 objectName 훅에 기대는
  위젯이 남아 있어 지우지 않았다. 남은 훅을 없애면 두 함수를 함께 지운다.
