# 01 · Claude Code <-> Claude Design 왕복 절차

이 재설계는 **플랜 검토 왕복**을 전제로 만들어졌습니다. 순서를 지켜 주세요.

## 왜 왕복하는가

디자인 프로토타입은 다음을 알 수 없습니다:
- 현재 코드의 리팩터링 여력, 테스트 커버리지, 릴리스 일정
- `qfluentwidgets` 버전에 실제로 존재하는 위젯/아이콘
- 성능 제약(수천 die, 599장 썸네일)의 실측값

반대로 Claude Code는 다음을 알 수 없습니다:
- 왜 그 색·간격·모션이 그 값인지, 무엇이 타협 가능하고 무엇이 게이트인지
- 화면 간 일관성 규칙(예: accent 3역할 분리, 미매칭 회색 1단)

그래서 **구현 전에 한 번, 플랜 단위로** 맞춥니다.

---

## STEP 1 - Claude Code: 플랜 + 질의 작성

`06-PLAN-TEMPLATE.md`를 복사해 `PLAN-01.md`로 채웁니다. 반드시 포함할 것:

1. **환경 실측** - `qfluentwidgets.__version__`, Qt 바인딩, Python 버전, 설치된 Fluent 패키지가 1개인지
2. **작업 분해** - 화면 10개를 몇 개의 PR/커밋으로 쪼갤지, 순서와 이유
3. **파일별 변경 계획** - `app/ui/*.py` 각 파일을 신규/전면교체/부분수정 중 무엇으로 할지
4. **위젯 매핑 확정안** - `02-design-rules.md` §5 표를 실제 존재하는 클래스명으로 채운 것
5. **FluentIcon 매핑** - 화면별 아이콘을 실제 열거값으로 (없으면 커스텀 아이콘 계획)
6. **성능 계획** - 수천 die 히트맵, 599장 썸네일, 12칸 판독대 동시 로드
7. **테스트 계획** - `tests/test_ui_smoke.py`가 깨질 범위와 대응
8. **질의 목록** - 아래 형식으로

### 질의 작성 형식 (이 형식을 지켜야 답변이 정확합니다)

```markdown
### Q1. [한 줄 질문]
- **분류**: 토큰 | 모션 | 레이아웃 | 카피 | 동작 | 성능 | 범위 | 충돌
- **근거 파일**: 03-screens.md §2 / app/ui/heatmap_dialog.py:77
- **현재 상황**: (코드가 지금 어떻게 되어 있는지 - 실제 라인 인용)
- **충돌 내용**: (디자인 명세와 무엇이 어긋나는지)
- **내 제안 A**: (구현 관점에서 이렇게 하고 싶다) - 비용: 낮음/중간/높음
- **내 제안 B**: (대안) - 비용: ...
- **원하는 답 형태**: A/B 택1 | 새 값 지정 | 규칙 확인 | 범위 조정
```

**질의를 잘 쓰는 법**
- "이거 어떻게 하죠?"(X) → "X가 Y와 충돌하는데 A/B 중 무엇?"(O)
- 항상 **제안을 먼저** 내세요. 판단 근거를 붙이면 그대로 승인되는 경우가 많습니다.
- 코드 라인을 인용하세요. 추측으로 물으면 추측으로 답이 옵니다.
- 한 질문에 한 결정만. 묶으면 답이 갈라집니다.
- 우선순위를 표시하세요: `[BLOCKER]` (이게 안 풀리면 착수 불가) / `[택1]` / `[확인]`

**질의 개수 가이드**: 8~20개. 5개 미만이면 플랜을 덜 파본 것이고, 30개 초과면 묶임이 부족한 것입니다.

작성 후 `PLAN-01.md`를 사용자에게 전달하고 **STEP 2를 기다립니다. 구현을 시작하지 마세요.**

## STEP 2 - Claude Design: 검토서 작성

Claude Design은 `PLAN-01.md`를 받아 `REVIEW-01.md`를 씁니다. 형식:

```markdown
# REVIEW-01

## 판정
승인 | 조건부 승인 | 재작성 필요

## 플랜 지적사항
| # | 위치 | 문제 | 조치 |

## 질의 응답
### A1 → Q1
- **결정**: (택1 결과 또는 새 값)
- **이유**: (왜 - 규칙 근거)
- **정확한 값**: (색 hex / ms / px / 문구를 복붙 가능한 형태로)
- **타협 가능 여부**: 게이트(불가) | 권장(가능, 조건부)

## 추가 지시
(플랜에 없지만 반드시 지켜야 하는 것)

## 다음 단계
(PLAN-02 작성 필요 여부, 착수 승인 범위)
```

**Claude Design 응답 규칙** (Claude Code가 바로 쓸 수 있는 형태로):
- 모든 값은 **복붙 가능한 리터럴**로 줍니다. "조금 더 어둡게"(X) / `#005A9E`(O)
- 모든 결정에 **게이트 / 권장** 표시를 답니다. 게이트는 타협 불가, 권장은 조건부 변경 가능
- 코드 예시는 **Python + qfluentwidgets** 로 씁니다 (CSS로 답하지 않음)
- 범위 축소 제안이 오면 **무엇을 버리고 무엇을 지킬지** 명시적으로 답합니다

## STEP 4 - 구현 중 재질의

구현하다 막히면 `QUESTIONS-<번호>.md`로 STEP 1의 질의 형식만 써서 물어보세요.
플랜 전체를 다시 쓰지 마세요.

**즉시 물어야 하는 경우**
- `02-design-rules.md`의 **게이트**를 지킬 수 없을 때 (대비 5.0, accent 3역할, 미매칭 회색 1단, 12 layer 판독대)
- 프로토타입 동작이 현재 코드 동작과 **모순**될 때
- 명세에 없는 상태(빈 값, 에러, 권한 없음)를 만났을 때
- `qfluentwidgets`에 그 위젯이 **없을** 때

**묻지 않고 진행해도 되는 경우**
- 프로토타입의 글리프를 FluentIcon으로 바꾸는 것 (매핑은 PLAN에서 확정)
- Qt 레이아웃 관용구로 같은 결과를 내는 것 (QVBoxLayout stretch 등)
- 변수/함수 이름, 파일 분할 방식
- 프로토타입 웹폰트를 시스템 폰트로 대체하는 것
