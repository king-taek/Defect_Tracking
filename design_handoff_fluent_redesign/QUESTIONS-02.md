# QUESTIONS-02 · 라이트 테마 대비 게이트 미달 4쌍

작성: Claude Code · 형식: `01-PROTOCOL.md` STEP 1 질의 형식
계기: REVIEW-01 "다음 단계 4 - 라이트/다크 중 한쪽만 게이트를 통과하는 토큰 조합은 즉시 질의"

`02-design-rules.md` §1 토큰을 그대로 상수화하고 AD3 공식(WCAG 상대 휘도)으로 전 조합을 계산한
결과, **다크 테마는 17쌍 전부 통과**했지만 **라이트 테마 4쌍이 게이트(5.0) 미달**입니다.
네 쌍 모두 4.5 이상이라 WCAG AA(4.5) 는 통과하고, 우리 자체 게이트 5.0 만 못 넘습니다.

측정은 `app/ui/theme.py` 의 `contrast()` 로 했고 회귀 테스트
`tests/test_tokens.py::test_contrast_gate` 에 전 조합이 박혀 있습니다. 네 쌍은 답을 받기 전까지
**strict xfail** 로 두었습니다(몰래 완화하지 않기 위함. 토큰을 고쳐 통과시키면 XPASS 로 즉시 드러남).

## 측정값 (라이트)

| 전경 | 배경 | 현재 대비 | 판정 |
|---|---|---|---|
| `onAccent` #FFFFFF | `accentFill` #0078D4 | **4.53** | 미달 |
| `pass` #0F7B0F | `passBg` #DFF6DD | **4.76** | 미달 |
| `warn` #9D5D00 | `warnBg` #FFF4CE | **4.77** | 미달 |
| `danger` #C42B1E | `dangerBg` #FDE7E9 | **4.79** | 미달 |
| (그 외 라이트 13쌍) | | 5.75 ~ 17.58 | 통과 |

참고 - 다크 동일 쌍은 전부 통과: onAccent/accentFill 9.17 · pass 6.14 · warn 8.64 · danger 6.20
(다크 상태 배경은 알파값이라 `card` #2B2B2B 위에 합성한 뒤 계산했습니다.)

### Q15. [BLOCKER] 라이트 accent 채움 위 흰 글자가 4.53 - 게이트 예외인가 값 조정인가

- **분류**: 토큰
- **근거 파일**: `02-design-rules.md` §0 게이트 1(대비 5.0) / §1.3 accent 표
  (`accentFill` 라이트 `#0078D4`, `onAccent` `#FFFFFF`), 측정 `tests/test_tokens.py`
- **현재 상황**: `#FFFFFF` on `#0078D4` = **4.53**. 이 조합은 주요 액션 버튼(＋ 출력에 담기,
  Excel 출력, LOT 폴더 선택), nav 배지, 선택 pill 에 전부 쓰입니다.
- **충돌 내용**: §1.3 의 확정값을 그대로 쓰면 §0 게이트 1을 못 지킵니다. 다크는 `onAccent`
  near-black 덕에 9.17 로 통과하므로, 라이트만 예외가 됩니다.
- **내 제안 A**: 이 쌍만 **4.5(WCAG AA) 예외로 명문화**. 이유: `#0078D4` + 흰 글자는 Windows·Fluent
  표준 조합이고, `setThemeColor` 기본값이기도 해서 바꾸면 OS 표준과 어긋납니다. 큰 글자(18.66px
  이상 또는 14px bold)는 WCAG 기준 3.0 이므로 실제 버튼 라벨(12.5px/600)만 경계에 걸립니다.
  비용: 낮음 (게이트 문서에 예외 1줄 추가)
- **내 제안 B**: `accentFill` 을 라이트에서만 어둡게 조정. 계산해 둔 후보 -
  `#0071C7`(5.02, 최소 변경) / `#006CBE`(5.40) / `#0067B8`(5.78, Fluent 이전 세대 표준색).
  `accentHover`·`accentPressed` 도 같은 폭으로 내려야 하며 `accentText` #005A9E 는 그대로 둡니다.
  비용: 중 (accent 계열 4값 재조정 + 프로토타입 스크린샷과 미세한 색차)
- **원하는 답 형태**: A/B 택1. B 라면 `accentFill`/`accentHover`/`accentPressed` 확정 hex 3개

### Q16. [BLOCKER] 상태색 3쌍(pass·warn·danger)이 4.76~4.79 - 동일 판단 필요

- **분류**: 토큰
- **근거 파일**: `02-design-rules.md` §1.4 상태색, §0 게이트 1
- **현재 상황**: 라이트에서 `pass` 4.76 / `warn` 4.77 / `danger` 4.79. 셋 다 "연한 배경 + 진한 글자"
  구조라 같은 이유로 같은 폭만큼 모자랍니다. 쓰이는 곳: 판독 카드 Δ 수치(pass), 미매칭 사유
  배지(warn/danger), InfoBar 4종, 폴더 선택 판정 칩.
- **충돌 내용**: Q15 와 동일하게 §1.4 확정값과 게이트 1이 충돌합니다.
- **내 제안 A**: Q15 와 **같은 결론을 적용**(A면 4.5 예외, B면 값 조정)해서 accent 와 상태색이 서로
  다른 기준을 쓰지 않게 합니다. 비용: 낮음
- **내 제안 B**: 글자만 한 단 어둡게. 계산해 둔 최소 변경 후보 - `pass` `#0F770F`(5.01) /
  `warn` `#985A00`(5.03) / `danger` `#BE2A1D`(5.03). 여유를 두려면 `#0B6A0B`(5.96) /
  `#8A5200`(5.80) / `#B02218`(5.76). 배경 3색은 그대로 둡니다. 비용: 낮음
- **원하는 답 형태**: A/B 택1. B 라면 `pass`/`warn`/`danger` 확정 hex 3개
  (여유값과 최소변경값 중 어느 쪽인지 함께)

### Q17. [확인] 게이트 1의 적용 대상 정의 - 채움 위 글자와 아이콘도 포함인가

- **분류**: 토큰
- **근거 파일**: `02-design-rules.md` §0 게이트 1("텍스트/배경 전 조합"), §2 "12px 이하 규칙"
- **현재 상황**: 테스트는 지금 17쌍(본문 3단계 × 표면 3종, accent 채움 위 글자, accent 글자 3종,
  상태 4종)을 검사하고, `txtDeco` 는 장식 전용이라 제외했습니다.
- **충돌 내용**: "전 조합"의 경계가 문서에 정의돼 있지 않습니다. 예를 들어 아이콘 글리프,
  비활성(disabled) 상태, 사진 위 흰 글자(#000 무대 위 62% 흰색 = 판독대 미매칭 문구)가
  대상인지 불명확합니다.
- **내 제안**: 게이트 대상 = **읽어야 하는 텍스트 + 의미를 나르는 글리프**. 제외 = `txtDeco`
  (구분자 · / 만), 비활성 상태(의도적 약화), 순수 장식 선·테두리. 사진 위 텍스트는 무대가 항상
  #000 이므로 별도 쌍으로 추가(측정: 흰 62% = 7.84, 흰 66% = 8.83, 스케일바 흰 55% = 6.25 로
  전부 이미 통과).
  비용: 낮음
- **원하는 답 형태**: 규칙 확인 (제외 목록 확정)

## 진행 방식

- Q15/Q16 답변 전까지 `theme.py` 의 해당 토큰은 `02-design-rules.md` 값 그대로 두고,
  테스트만 strict xfail 로 표시해 둡니다. 답변이 오면 토큰 수정과 xfail 제거를 같은 커밋에서 합니다.
- Q17 은 테스트 대상 목록에만 영향이 있어 구현을 막지 않습니다.
- 이 4쌍을 제외한 나머지 토큰·모션·형태 값은 REVIEW-01 "착수 승인 범위 1번"대로 이미 상수화하고
  회귀 테스트를 붙였습니다.
