# QUESTIONS-03 · REVIEW-02 구현 중 발견한 게이트 충돌 5건

작성: Claude Code · 형식: `01-PROTOCOL.md` STEP 1 질의 형식
계기: REVIEW-02 의 A15 규칙·A17 대상 목록을 코드로 옮기며 명세 그대로 계산해 본 결과,
게이트를 못 지키거나 표와 어긋나는 지점이 나왔습니다. STEP 4 "즉시 물어야 하는 경우"에 해당합니다.

전제: A16(상태색)은 그대로 반영했고 회귀 테스트로 고정했습니다. A15·A17 도 아래 보완을 적용해
**현재 전 프리셋·전 상태가 게이트를 통과**합니다. 아래는 그 보완이 맞는지 확인받는 질의입니다.

측정은 `app/ui/theme.py` 의 `contrast()` 로 했고 값은 재현 가능합니다.

### Q18. [BLOCKER] clamp 루프가 게이트 미달로 종료된다 (다크 + 고채도 accent)

- **분류**: 토큰
- **근거 파일**: REVIEW-02 A15 의 `resolve_accent()` 의사코드 (`fill.lighter(106)` 반복)
- **현재 상황**: `lighter(106)` 은 HSV 의 명도(V)에만 배율을 곱합니다. 고채도 색은 한두 번 만에
  V=1.0 으로 포화하고, 그 뒤 반복은 **아무 변화가 없습니다.** guard 24회를 소진한 뒤 미달 상태로
  그냥 빠져나옵니다.
  ```
  다크 #8B5CF6 : 0회 4.35 → 6회 #905FFF(V=1.000) 4.62 → 12회 4.62 → 24회 4.62  (게이트 미달로 종료)
  ```
- **충돌 내용**: "어떤 accent 를 받아도 게이트를 지킨다"는 규칙의 목적이 깨집니다. 조용히 실패하는
  경로라 더 위험합니다.
- **내 제안 A**: **V 포화 후 채도(S)를 낮춰 이어갑니다.** 문서화된 다크 accent `#4CC2FF` 가
  채도 낮은 파랑인 것과 같은 원리입니다. 적용 결과 `#8B5CF6` 다크 → `#9769FF`(5.07). 극단색·무작위색
  264조합을 넣어도 미달 0건입니다. 비용: 낮음 (이미 구현·검증 완료)
- **내 제안 B**: 프리셋 화이트리스트 밖의 커스텀 accent 를 아예 막습니다. 비용: 낮음(기능 축소)
- **원하는 답 형태**: A/B 택1 (나는 A 제안)

### Q19. [택1] clamp 목표를 5.0 으로 두면 A16 의 "여유" 논리와 어긋난다

- **분류**: 토큰
- **근거 파일**: REVIEW-02 A15(`ACCENT_GATE = 5.0`), A16("최소변경값은 배경이 조금씩 달라질 때
  다시 미달로 떨어진다"며 여유값 채택)
- **현재 상황**: 규칙은 5.0 을 **처음 넘는 값에서 멈춥니다.** 라이트 `#0078D4` 를 그대로 넣으면
  1회 만에 `#0071C8`(**5.00**)에서 종료됩니다. 이는 A15 가 "알파 합성·감마 차이에서 다시 미달로
  떨어진다"며 거부한 `#0071C7`(5.02)과 사실상 같은 값입니다.
  ```
  라이트 #0078D4 clamp 궤적
    0회 #0078D4 4.53 / 1회 #0071C8 5.00 / 2회 #006BBD 5.47 / 3회 #0065B2 5.99 / 5회 #005A9E 7.10
  ```
- **충돌 내용**: 같은 검토서 안에서 상태색은 여유(5.7 이상), accent 는 최소(5.00)로 서로 다른
  기준이 됩니다.
- **내 제안 A**: 목표를 그대로 5.0 으로 두되, **프리셋 3종은 A15 표의 확정값을 상수로 고정**해
  실제 사용 경로에서는 여유를 확보합니다(현재 구현). 커스텀 색만 5.0 경계에 걸칩니다. 비용: 낮음
- **내 제안 B**: `ACCENT_CLAMP_TARGET` 을 5.4~5.7 로 올려 커스텀 색도 여유를 갖게 합니다.
  5.4 면 `#0078D4` → `#006BBD`(5.47). 비용: 낮음(상수 1개)
- **원하는 답 형태**: A/B 택1 또는 목표값 지정

### Q20. [확인] A15 표의 hex 일부는 제시된 알고리즘으로 도달할 수 없다

- **분류**: 토큰
- **근거 파일**: REVIEW-02 A15 "기본 프리셋 3종의 해결값(회귀 테스트에 이 표를 박아 두세요)"
- **현재 상황**:
  | 프리셋 | 표 값 | 알고리즘 결과 | 차이 |
  |---|---|---|---|
  | 라이트 `#0078D4` | `#0067B8` (5.78) | `#0071C8` (5.00) | 반복 횟수 |
  | 라이트 `#8B5CF6` | `#7B3FE4` (5.72) | `#7C52DB` (5.14) | **채도가 올라간 값이라 V 스케일로 생성 불가** |
  | 라이트 `#009FAA` | 조정 없음 (5.73) | 조정 없음 (5.73) | 일치 |
- **충돌 내용**: 표와 알고리즘 중 하나만 만족시킬 수 있습니다.
- **내 제안**: **표 값을 프리셋 상수로 고정**하고(지시대로 회귀 테스트에 박음), 규칙은 표에 없는
  임의 색에만 적용하는 안전망으로 둡니다. 두 지시를 모두 만족합니다. 비용: 낮음(구현 완료)
- **원하는 답 형태**: 규칙 확인

### Q21. [BLOCKER] 하위 기준 3.0 을 경계선 토큰에 적용하면 §1.1·§1.2 확정값이 전부 미달

- **분류**: 토큰
- **근거 파일**: REVIEW-02 A17 하위 기준 대상(`ctrlBd`/`ctrlBdBottom` × `ctrlBg`,
  `cardBorder` × `layer`), `02-design-rules.md` §1.1·§1.2
- **현재 상황**: Fluent 경계선은 의도적으로 알파 .058~.16 이라 3.0 근처에도 못 갑니다.
  ```
  라이트  ctrlBd/ctrlBg 1.17 · ctrlBdBottom/ctrlBg 1.44 · cardBorder/layer 1.13 · cardBorderH/layer 1.45
  다크    1.32 · 1.32 · 1.24 · 1.69
  포커스 링(accentFill) on card/layer/win = 4.53 / 4.30 / 4.08 (라이트), 7.06 / 7.45 / 8.12 (다크)  -> 통과
  ```
- **충돌 내용**: A17 은 "경계선에 5.0 을 요구하면 Fluent 룩이 깨지므로 3.0" 이라고 했는데, 3.0 도
  같은 이유로 깨집니다. 토큰을 3.0 까지 올리면 §1.1·§1.2 를 폐기하는 셈입니다.
- **내 제안 A**: 하위 기준 대상을 **포커스 링·선택 링으로 한정**하고(둘 다 통과), 카드·컨트롤
  경계선은 "장식 + 형태 보조"로 분류해 제외합니다. 근거: 컨트롤 식별은 채움·그림자·레이아웃이
  담당하며 경계선이 유일한 식별 수단이 아닙니다. 비용: 낮음
- **내 제안 B**: 경계선 토큰을 3.0 이상으로 올립니다(라이트 `cardBorder` 를 rgba(0,0,0,.35) 수준까지).
  Fluent 외관과 프로토타입 스크린샷이 함께 바뀝니다. 비용: 높음
- **원하는 답 형태**: A/B 택1 (나는 A 제안). 현재는 해당 4쌍을 strict xfail 로 표시해 두었습니다

### Q22. [확인] 히트맵 선택 링이 최고 밀도 die 위에서 보이지 않는다

- **분류**: 충돌
- **근거 파일**: `03-screens.md` §3("선택: `2px accentFill` 테두리", "단일 잉크 램프 accentFill
  알파 0.12→1.0"), REVIEW-02 A17("히트맵 선택 링 × 램프 최저·최고 채움 양쪽")
- **현재 상황**: 램프의 최고 채움이 곧 `accentFill` 이고 선택 링도 `accentFill` 이라 **같은 색**입니다.
  ```
  선택 링 vs 램프 최저 채움 = 4.02(라이트) / 5.44(다크)   -> 식별 가능
  선택 링 vs 램프 최고 채움 = 1.00                        -> 완전히 동일, 보이지 않음
  ```
- **충돌 내용**: defect 이 가장 많은 die(=가장 주목해야 할 die)를 선택하면 선택 표시가 사라집니다.
- **내 제안 A**: 선택 링을 **흰색/near-black 이중선**으로(안쪽 1px `onAccent`, 바깥 1px `accentFill`).
  램프 어느 지점에서도 최소 한 겹이 대비를 만듭니다. 비용: 낮음
- **내 제안 B**: 램프 상한을 알파 0.85 로 낮춰 최고 채움과 선택 링을 분리합니다. 비용: 낮음
  (밀도 최고 구간의 표현력이 약간 줄어듭니다)
- **원하는 답 형태**: A/B 택1 + 링 두께. 단계 6(히트맵) 착수 전까지 답변이 필요하며,
  지금 당장 구현을 막지는 않습니다

## 추가로 발견한 사항 (질의 아님, 이미 처리)

REVIEW-02 A15 의 `hover`/`pressed` 파생식(`darker(112)`/`darker(126)`)을 그대로 쓰면 **밝은 채움 +
near-black 글자** 조합에서 상태 변화 시 대비가 떨어집니다.
```
라이트 #009FAA : fill 5.73 → hover(어둡게) 4.66 → pressed(어둡게) 3.85   (미달)
```
`onAccent` 가 near-black 인 채움은 hover·pressed 를 **밝은 쪽**으로 옮기도록 방향을 뒤집었습니다
(프로토타입의 QFluent 프리셋 hover `#00B7C3` 도 밝은 쪽입니다). 같은 이유로 글자용 accent(`text`)는
페이지 면 대비로 별도 clamp 합니다. 다른 결정을 원하시면 알려 주세요.
